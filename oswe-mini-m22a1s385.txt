## 3.4 New System Design (Greenfield Replacement)

Design goals:
- Correct path calculation (Dijkstra for non-negative graphs, Bellman-Ford for negative allowed graphs).
- Stateless routing service with pluggable persistence and a transactional outbox pattern for events (migration/dual-write).
- Idempotency & retries for safe request replay.
- Structured logging with request/appointment IDs.

Service decomposition (ASCII):

- API Gateway -> Routing Service (stateless) -> Graph Store (persistent)  
  |-> Metrics/Tracing |-> Outbox Service (event sink) |-> Reconciler job

Data flow:
- Client -> HTTP API -> Router computes path:
  - Validate graph edges
  - Select Dijkstra or Bellman-Ford
  - Return path + cost
- Optionally emit events to Outbox for async persistence/replication

Key Interfaces (proposals):
- RouteRequest: {request_id: str, start: str, goal: str, graph_id?: str, idempotency_key?: str}
- RouteResponse: {request_id: str, path: [str], cost: float, runtime_ms: float}
- Field constraints: node names length <= 32 chars, cost numeric float, idempotency_key <= 64 chars.

Idempotency model:
- Implement idempotency key stored in persistent store (in-memory example in utils) → For distributed use, use Redis/DB.

Retry model:
- Retry decorator with exponential backoff; maximum attempts configurable; idempotency ensures safe retries.

Circuit-breaker/timeouts:
- Use timeouts around compute and external calls; circuit breaker at network/adapter layer.

Compensation:
- Saga/Outbox: actions recorded in outbox; failed step triggers compensation flow; reconciliation job periodically compares outbox and actual state.

Migration & parallel run:
- Dual-write: write to both legacy and v2 graph stores for a transitional period. Use shadow traffic to call v2 for a sample percentage of requests to validate outputs.
- Backfill: snapshot graphs into v2 store; run reconciliation jobs to detect drift.
- Rollback: traffic routing flag; revert to legacy routing on failure metrics.

   - Observability: path, cost metrics

3) Target: Negative cycle detection  
   - Preconditions: graph with negative cycle  
   - Steps: run Bellman-Ford  
   - Expected: raise error "negative-weight cycle"  
   - Observability: error metric, failure rate

4) Target: Idempotency behavior  
   - Preconditions: idempotency key provided  
   - Steps: call idempotent function twice with same key  
   - Expected: result returned once, subsequent is no-op; call count=1  
   - Observability: idempotency hit/miss counter

5) Target: Retry + timeout behavior  
   - Preconditions: flaky function raising transient first  
   - Steps: call decorated function with retry/backoff and timeout  
   - Expected: returns success after retry; attempts >= 2; no exception at end  
   - Observability: retry count, timeouts metric

6) Target: Outbox and compensation (Saga)  
   - Preconditions: step2 fails  
   - Steps: run saga (step1, step2); on failure emit compensation event  
   - Expected: compensation event in outbox; cleanup recorded  
   - Observability: outbox events list, compensation metric
